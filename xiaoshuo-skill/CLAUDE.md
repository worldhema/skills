# 小说书 · AI 创作框架

> 本仓库是一套本地小说创作 Agent 系统（主技能总控）。参考 WorkBuddy 社区分享的「5阶段框架 + 9技能体系 + 单章7步自动化循环」方法论搭建。
> **核心理念：把全书设定、人物边界、剧情约束变成必须死守的强制规则，用流程锁住 AI，避免「开篇惊艳、后期崩盘」。**

## 一、项目结构（5 个工作空间）

| 目录 | 职责 |
|------|------|
| `01-大纲细纲/` | 全书大纲、分卷细纲、章节细纲 |
| `02-正文存稿/` | 正文章节文件，命名 `第XXX章-标题.md` |
| `03-设定文档/` | 世界设定、人物设定、写作风格、伏笔追踪、红线规则、合规敏感词清单 |
| `04-技能配置/` | 9 个技能的详细说明书（输入/输出/步骤/注意事项） |
| `05-版本备份/` | git 版本历史说明（版本备份由 git 承载） |

## 二、5 阶段创作流程

1. **工作空间初始化** — 目录结构已就绪；新书 = 复制本框架为 `小说书-书名`，或在本目录直接初始化。
2. **技能体系搭建** — 9 技能定义在 `.claude/skills/`（可调用入口）+ `04-技能配置/`（详细规范）。技能体系即本仓库，无需每次重建。
3. **前期创作准备** — 用户说「初始化一本新书」时执行：确定类型/目标平台 → 搜集同类型网文参考 → 生成**世界全设定表格** → 人物设定 → 全书大纲 → 黄金三章 → 写作风格样本。产物写入 `03-设定文档/` 与 `01-大纲细纲/`。这是全书质量的根基，必须做扎实后再进入阶段4。
4. **单章标准化创作** — 每章严格走下方 7 步循环。
5. **审查与修改** — 每 **5 章** 为一个单位做整体审查（逻辑、剧情连贯、文笔、伏笔回收、人物一致性），发现的问题自动修正。审查建议切换 pro 模型（`/model` → deepseek-v4-pro），推理能力更强。

## 三、9 技能体系

**1 个主技能 + 7 个子技能 + 1 个自动化技能**，定义于 `.claude/skills/`，详细规范见 `04-技能配置/`：

| 技能 | skill 名称 | 职责 |
|------|-----------|------|
| 主技能 | `novel-chapter` | 平台小说章节全流程创作，统筹调度，不直接生成正文 |
| 子技能1 | `novel-prep` | 资料整理与前文梳理：前文剧情、人物状态、未回收伏笔 |
| 子技能2 | `novel-outline` | 单章剧情推演：基于大纲推演本章核心冲突与转折 |
| 子技能3 | `novel-write` | 平台标准正文生成：约 2000 字，去 AI 味 |
| 子技能4 | `novel-review` | 合规与一致性审查：OOC、剧情矛盾、平台合规 |
| 子技能5 | `novel-polish` | 内容优化打磨：润色对话、增强画面感、调整节奏与钩子 |
| 子技能6 | `novel-track` | 故事线与人物线更新：更新人物状态表、伏笔追踪表 |
| 子技能7 | `novel-backup` | 自动版本备份：每章 git commit |
| 灵感技能 | `novel-method` | 创作方法与剧情灵感引擎：冲突/英雄之旅/写作手法/人物弧光的灵感生成 |
| 自动化技能 | `novel-scan` | 每日存稿备份 + 合规扫描（敏感词/违规风险） |

**技能配置原则**：① 每个技能只做一件事，输入输出边界清晰；② 技能之间串联调用形成流水线；③ 主技能负责调度，不直接生成内容；④ 自动化技能独立于主流程，做兜底保障。

**创作方法论**：戏剧冲突（5 类 + 欲望/阻碍/代价）、英雄之旅（千面英雄 12 步）、三幕结构、写作手法、人物弧光、场景四要素、灵感生成法，见 `04-技能配置/创作方法论.md`。
- 阶段3 大纲设计：用「英雄之旅对照表」规划全书骨架（见 `01-大纲细纲/全书大纲.md`）。
- 阶段4 剧情推演：先确定本章冲突类型与章末钩子类型。
- 卡文或需灵感时：调用 `novel-method`。

## 四、单章 7 步循环（强制）

每创作一章，**必须按顺序走完以下 7 步**，不可跳步、不可合并：

| 步骤 | 动作 | 对应技能 |
|------|------|---------|
| 1 资料整理 | 读取 `03-设定文档/` 人物状态、前文梗概、未回收伏笔 | `novel-prep` |
| 2 剧情推演 | 基于大纲+细纲，推演本章 3~5 个核心事件、冲突、转折、章末钩子 | `novel-outline` |
| 3 正文生成 | 按细纲生成约 2000 字初稿，内置去 AI 味处理 | `novel-write` |
| 4 合规审查 | 检查人物 OOC、剧情矛盾、平台规则合规（违禁词/敏感描写） | `novel-review` |
| 5 内容打磨 | 如审查发现问题则针对性修改；润色对话、增强画面感、优化章末钩子 | `novel-polish` |
| 6 故事线更新 | 更新人物状态表、伏笔追踪表、本章梗概 | `novel-track` |
| 7 自动备份 | git commit（`feat(chapter): 第XXX章-标题`） | `novel-backup` |

**触发方式**：用户说「写第 X 章」「创作下一章」等，加载主技能 `novel-chapter` 按上表执行。创作前建议先与用户讨论本章方向，再动笔。

## 五、强制规则（不可违反）

以下约束为「全书级硬规则」，每章创作前必须重新读取 `03-设定文档/`：

1. **红线规则**（`03-设定文档/红线规则.md`）— 用户明确不能碰的内容，正文绝不允许出现。
2. **人物一致性** — 任何人物的言行不得背离 `人物设定.md` 中的性格、目标、OOC 红线。发现偏差立即修正而非将错就错。
3. **伏笔回收** — 已埋设伏笔按 `伏笔追踪.md` 计划回收，正文不得与未回收伏笔冲突，也不得遗忘。
4. **去 AI 味** — 正文须对照 `写作风格.md`：禁用列表、抽象总结句、模板化开头结尾，追求具体画面与真实对话感。
5. **合规底线** — 不出现 `合规敏感词清单.md` 中的违禁内容；政治、色情、暴力描写从严把控。

## 六、目录与文件约定

- 章节命名：`第001章-标题.md`、`第002章-标题.md`（三位数递增）。
- 章节细纲放 `01-大纲细纲/章节细纲/第XXX章-细纲.md`，正文放 `02-正文存稿/第XXX章-标题.md`。
- 每次创作章节时，同步更新 `03-设定文档/伏笔追踪.md`、`人物设定.md`（当前状态）、`01-大纲细纲/分卷细纲.md`（进展）。
- 每 5 章在 `05-版本备份/` 下记录一次里程碑说明（`第XXX章-里程碑.md`）。

## 七、Git 备份约定

- 每完成一章：`git add` 全部改动 → `git commit -m "feat(chapter): 第XXX章-标题"`。
- 完成阶段3 初始化或重大设定变更：`feat(setting): <描述>`。
- 审查修正：`fix(chapter): 第XXX章 审查修正`。
- 版本历史查看与回滚命令见 `05-版本备份/说明.md`。

## 八、模型建议

创作（正文生成、剧情推演）建议使用 pro 模型（`/model` 切换至 deepseek-v4-pro）以保证文笔与连贯性；资料整理、备份等机械环节可用默认模型。系统会按各环节需要提示。
